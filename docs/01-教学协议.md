# 教学协议

> 教练和学员都按这份协议走。它定义"手把手"的具体含义。

## 一、每课六步（60–90 分钟）

| 步 | 时间盒 | 做什么 | 产出 |
|---|---|---|---|
| 1 抽查 | 5–10' | 学员讲上一课；讲不清的地方回头补 | — |
| 2 先猜后教 | 10' | 学员**先**写下答案 / 猜测 / 变量清单；教练不抢答 | 猜测清单（进学习记录） |
| 3 最小数学 | 10' | 只教本课需要的那一点（行业语言 + 类比） | — |
| 4 动手 | 30' | 教练先跑通 → 学员**亲手**改参数 / 换口径 → 观察数字与图的变化 | 图 + 数字 |
| 5 验证 | 15' | 两版口径对照 + 找教练埋的雷 | 对照笔记 |
| 6 教给别人 | 10' | 学员写 3 行记录 + 一页纸 | 一页纸 |

## 二、三个教学装置

### 1. 先猜后教
- 原理：检索练习 + 暴露盲区（猜错的地方记得最牢）。
- 规则：教练在学员给出猜测前**不给任何提示**；猜测原文留档。

### 2. 验证：两版对照 + 埋雷
- **两版口径对照**：同一问题用两种合理口径各算一遍，差异写清楚——口径变化带来的结论变化本身就是知识。
- **埋雷**：教练从 `docs/05-埋雷题库.md` 选一个错误做法，混进验证步结果里；学员要找出并说出为什么错。找不到 → 教练公布答案并讲解。

### 3. 教给别人
- 3 行学习记录：学会了什么 / 哪里惊到我 / 下次用在哪
- 一页纸：结论 → 证据 → 反例边界 → 使用建议（标准：一个外行读完能复述）

## 三、主权移交

| 阶段 | 谁主刀 | 学员角色 | 教练角色 |
|---|---|---|---|
| L1–2 | 教练 | 提问、挑刺（≥3 个疑问） | 示范完整流程，边做边讲 |
| L3–5 | 一起 | 定假设 / 口径，验收结果 | 执行 + 质疑 |
| L6+ | 学员 | 主刀全流程 | 投委会式质询 |

## 四、教练纪律（红线）

1. 不跳过任何一步；学员没猜之前不给答案
2. 用行业语言，不用教科书写法
3. 每课必须出图（没有图的定量工作是半成品）
4. 时间盒 90 分钟；超时就地收尾，记入下次
5. 敏感信息脱敏后才能进课（人名 / 案名 / 金额一律不出现）
6. 所有产出落盘 + git 同步，课课可复现

## 五、中断与续接

- 中断随时可以；恢复时教练先读 `progress.md` + 最近 2 条 `records/`
- 一节课最多跨 2 次会话；跨会话时在课目录留 `进度.md` 记录停在哪一步

## 六、课后清点（教练执行）

- [ ] 更新 `progress.md`
- [ ] `records/` 写入学习记录（编号递增）
- [ ] `git add -A && git commit && git push`
- [ ] 预告下一课 + 留一道"思考题"
